* eClinic Project
** Planning
  1. Phân tích yêu cầu (Requirements)
    - Trước khi code, bạn cần xác định các nhóm người dùng chính:
      + Bác sĩ: Xem lịch hẹn, nhập bệnh án, kê đơn thuốc.
      + Lễ tân/Nhân viên: Tiếp nhận bệnh nhân, sắp xếp lịch khám, thu phí.
      + Bệnh nhân: Đăng ký tài khoản, đặt lịch hẹn online, xem lịch sử khám.
      + Quản trị viên (Admin): Quản lý nhân sự, danh mục thuốc, báo cáo doanh thu.
  2. Thiết kế Cơ sở dữ liệu (Database Schema)
    - Đây là "xương sống" của ứng dụng. Bạn nên thiết kế các Model chính như sau:
      + Model 		| Các trường thông tin chính
      + User		| Mở rộng từ AbstractUser (Bác sĩ, Lễ tân, Bệnh nhân)
      + Patient		| Họ tên, Ngày sinh, Giới tính, Số điện thoại, Mã bệnh nhân
      + Appointment 	| Bệnh nhân, Bác sĩ, Ngày giờ khám, Trạng thái (Chờ, Đã khám, Hủy)
      + MedicalRecord	| Bệnh nhân, Bác sĩ, Chẩn đoán, Triệu chứng, Ngày khám
      + Prescription	| Hồ sơ bệnh án, Tên thuốc, Liều dùng, Số lượng
      + Invoice		| Hồ sơ bệnh án, Tổng tiền, Trạng thái thanh toán
  3. Lộ trình triển khai (Roadmap)
    - Giai đoạn 1: Thiết lập nền tảng
      + Cài đặt môi trường: Python, Django, và các thư viện cần thiết (django-crispy-forms cho giao diện, Pillow cho hình ảnh).
      + Khởi tạo Project và App (ví dụ: users, clinic, billing).
      + Thiết kế hệ thống Authentication (Đăng nhập/Đăng ký) phân quyền theo Role.
    - Giai đoạn 2: Phát triển chức năng lõi
      + Quản lý Bệnh nhân: CRUD (Thêm, sửa, xóa, tìm kiếm) thông tin bệnh nhân.
      + Đặt lịch hẹn (Booking): Xây dựng logic kiểm tra lịch trống của bác sĩ để tránh trùng lịch.
      + Hồ sơ bệnh án & Đơn thuốc: Giao diện cho bác sĩ nhập liệu nhanh.
    - Giai đoạn 3: Tài chính và Báo cáo
      + Tạo hóa đơn tự động dựa trên đơn thuốc và dịch vụ khám.
      + Trang Dashboard thống kê số lượng bệnh nhân và doanh thu theo ngày/tháng (Sử dụng Chart.js để vẽ biểu đồ).
  4. Gợi ý Tech Stack
    - Backend: Django (Python).
    - Database: PostgreSQL (Khuyên dùng cho môi trường thực tế) hoặc SQLite (Cho lúc phát triển).
    - Frontend: Bootstrap 5 hoặc Tailwind CSS để ứng dụng trông chuyên nghiệp và chạy tốt trên điện thoại.
    - Xử lý thời gian thực: Django Signals (Gửi thông báo khi có lịch hẹn mới).
  5. Các lưu ý quan trọng về Y tế
    - Bảo mật dữ liệu: Dữ liệu y tế rất nhạy cảm. Hãy đảm bảo sử dụng HTTPS và mã hóa các thông tin quan trọng.
    - Sao lưu (Backup): Thiết lập cơ chế tự động backup database hàng ngày.
    - Số hóa: Nên có chức năng xuất đơn thuốc hoặc bệnh án ra file PDF để in cho bệnh nhân.

** Lộ trình thực tế
- Lộ trình + Công cụ (ưu tiên miễn phí)
1. Phỏng vấn 1–2 phòng mạch thật
  - 🎯 Mục tiêu: hiểu nghiệp vụ & pain point
  - Công cụ: 📝 Google Docs / Notion. 🧠 Whimsical / Miro (free) → Vẽ nhanh flow nghiệp vụ thô
  - 📌 Tip IT: Ghi lại “họ làm thật”, không phải “họ nói nên làm”
2. Viết SRS rút gọn
  - 🎯 Mục tiêu: chốt phạm vi & chức năng
  - Công cụ: Google Docs (phổ biến nhất). Notion (nếu thích checklist + database). Markdown + Git (nếu thuần dev)
  - 📌 Nội dung tối thiểu: Actor. Use case. Non-functional (bảo mật, backup)
3. User Flow & Wireframe (LOW-FI) 🔥
  - 🎯 Mục tiêu: xác nhận luồng trước khi đụng data. User Flow: ai → làm gì → theo thứ tự nào
  - User Flow: Whimsical (free). Draw.io (diagrams.net) – rất ổn, free hoàn toàn. Miro free. Wireframe. Figma (free plan) ⭐ phổ biến nhất. Balsamiq (trial) (vẽ rất nhanh, low-fi đúng nghĩa). Pen & paper + chụp hình (không đùa đâu 😄). Excalidraw (miễn phí, online), Penpot (open-source thay Figma)
  - 📌 Tip IT: Wireframe chỉ cần:
    + Button. Form. Bảng. Không màu mè
    + Vì sao KHÔNG để Wireframe sau ERD? Sai lầm rất hay gặp:
      + Vẽ ERD trước
      + Code model xong
      + Bác sĩ dùng → “Sao phải click nhiều thế?”
      + 👉 User Flow = cách người ta làm việc
      + 👉 ERD = dữ liệu phục vụ cách đó
      + IT hiện nay làm ngược lại sẽ trả giá 😅
4. Vẽ ERD (Data Model)
  - 🎯 Mục tiêu: mô hình dữ liệu đúng nghiệp vụ. Dựa trên flow thực tế đã được xác nhận. (flow quyết định data, không phải ngược lại)
  - Công cụ: dbdiagram.io (free) ⭐ rất hợp dev. Draw.io. DBeaver (free) – nếu quen DB tool. Lucidchart (free hạn chế)
  - 📌 Tip Django:
    + Vẽ ERD xong → map trực tiếp sang models.py
5. Quyết stack (Django + PostgreSQL)
  - 🎯 Mục tiêu: chốt công nghệ, tránh đổi giữa chừng
  - Công cụ: Notion / Google Docs – ghi quyết định. Awesome Django (GitHub) – tham khảo package. StackShare (free) – xem hệ khác dùng gì
  - 📌 Stack gợi ý:
    + Django
    + Django REST Framework
    + PostgreSQL
    + Redis (sau này)

  - Frontend

7. Test với người dùng thật
  - 🎯 Mục tiêu: validate flow, không chỉ bug
  - Công cụ

  - 📌 Tip IT:
    + Quan sát chỗ user dừng lại lâu

8. Mở rộng & vận hành
  - 🎯 Mục tiêu: sống lâu, không chết sớm
  - Deploy

  - Monitoring
    + Sentry (free tier)
    + UptimeRobot (free)
  - Backup
    + Cron job
    + PostgreSQL dump
    + Google Drive / S3 free tier
